# Browser Gateway

[English](README.md) | 简体中文

一个可自行部署的服务器端浏览器网关：在 Linux 服务器运行真实浏览器，
用户通过普通电脑浏览器访问入口，即可操作原有网站。

网站渲染、持久化浏览器资料及上游网络连接都在服务器端完成。客户端接收
无损像素画面，并将键盘、鼠标、剪贴板和文件操作传递给自己的远程窗口。
无需安装客户端扩展、VNC 软件，也无需为原网站重写一套界面。

**当前源码基线：** 1.4.4 · Node.js 22+ · Linux amd64 · Docker Compose

## 功能

| 能力 | 实现方式 |
| --- | --- |
| 原网站画面 | 原网站在服务器 Google Chrome 中运行，客户端显示真实渲染结果，不是重新制作的网页界面。 |
| 独立操作窗口 | 每个客户端标签页拥有独立远程窗口、视口、焦点和输入流，同时共用一个持久化浏览器资料目录。 |
| 无损画面传输 | RGB 采集、QOI 编码、WebAssembly 解码与 WebSocket DEFLATE 保留采集像素，不采用有损视频压缩。 |
| 分辨率自适应 | 远程视口随客户端窗口尺寸和设备像素比调整，并遵循配置的物理像素上限。 |
| 常用交互 | 桥接鼠标光标、文字选择、拖动、滚轮、键盘快捷键和输入法组合输入。 |
| 触屏交互 | 手指点击和滑动交给服务器 Chrome 的触摸手势处理，桥接软键盘编辑与可见视口变化，并保留电脑端鼠标输入路径。 |
| 剪贴板与文件 | 在目标网站支持的情况下，桥接文字及支持的富文本复制、图片粘贴、文件拖放、文件选择和下载。 |
| 持久化共享状态 | Cookie、网站存储和浏览器资料在容器替换后保留；成员共享资料，而非使用相互隔离的账号。 |
| 管理员手动登录工作区 | 独占工作区显示服务器浏览器工具栏，支持使用原资料和网络配置人工完成登录。 |
| 按负载分配采集资源 | 增量采集变化区域，静止画面不重复发送，断开窗口停止采集，编码线程按活跃会话分配。 |
| 自动重连与流控 | 客户端自动重连，按序确认画面，采用最多两帧在途的有界流水线，避免画面无限积压。 |
| 后台资源节省 | 标签页隐藏满一分钟后自动断连、停止采集并暂停成员页面脚本；正常断连保留期内，返回后重连至同一会话。 |
| 浏览器空闲保活 | 最小化的空白窗口在所有成员会话过期后保留共享浏览器，不加载网站、不采集画面，也不占用成员名额。 |
| 统一网络出口 | 可配置上游浏览器代理，将网站出站访问集中在服务器端。 |
| 容器化运行 | 应用使用非 root 用户、只读容器根文件系统、项目内数据挂载、健康检查和可配置的数据保留周期。 |

默认采集上限为 **60 FPS**，物理画面上限为 **8192 × 4320**，
活跃会话上限为 **12**。这些是配置上限，不是实际性能承诺。

## 优势

- **保留原有界面。** 网站的布局和功能由真实浏览器运行，无需另行实现网站前端。
- **保留文字和界面细节。** 无损 RGB 传输避免常见 4:2:0 视频流的色度损失。
- **降低客户端部署负担。** 使用兼容的电脑或触屏浏览器即可，无需在每台设备安装服务器浏览器或配置其上游代理。
- **集中管理浏览器状态。** 一个受管理的资料目录统一保存 Cookie、字体环境与出站网络配置。
- **独立输入而不复制整套资料。** 用户无需争用同一个桌面鼠标，同时可以共享持久化浏览器资料。
- **便于审查和维护。** 源码、模板和测试纳入版本管理，运行数据与凭据留在 Git 之外。

可参考的部署场景包括内部仪表盘、课堂文档环境、网页演示终端，以及需要
受控服务器网络才能访问的授权 Web 工具。这些是架构适用场景，不表示已经
接入或验证所有第三方网站。

## 架构

```text
客户端浏览器
    ↕ 无损画面 + 键盘 / 鼠标 / 剪贴板 / 文件
Node.js 网关：会话管理与画面流控
    ↕
服务器 Chrome：一个持久化资料目录、各客户端独立窗口
    ↓
目标网站：直接访问或通过配置的上游代理访问
```

采集链路采用 Xvfb/Openbox、XComposite、XShm、XDamage 和 XFixes。
原生 C/C++ 程序负责 RGB 画面采集及手动工作区的输入，客户端通过
WebAssembly 重建 QOI 图块并绘制到画布。不对外发布 VNC 或 Chrome 调试端口。

这是一个**远程像素浏览器**，不是把原网站 DOM 转发给客户端的反向代理，
也不是账号和数据完全隔离的多租户浏览器服务。

## 安装

### 环境要求

- Linux **amd64** 主机，CPU 支持 **x86-64-v3** 指令集；原生采集器按这一指令集基线编译。
- 启用 BuildKit 的 Docker Engine，以及 Docker Compose v2。
- 与分辨率、用户数量相匹配的 CPU、内存和网络带宽。当前渲染和采集链路以 CPU 为主，不要求 GPU。
- 支持 Canvas、WebSocket 和 WebAssembly SIMD 的客户端浏览器。
  触屏设备还需要 Pointer Events；剪贴板权限和原生文件窗口由客户端浏览器控制。
- [vendor/README.md](vendor/README.md) 中说明的固定版本浏览器安装包。

以下命令用于**新部署**。已有部署应保留当前的 `.env`、私有 Compose 配置
和 `data/`，不要用示例文件直接覆盖它们。

### 1. 获取源码与构建依赖

```sh
git clone <repository-url-or-local-path> browser-gateway
cd browser-gateway
sh scripts/prepare-vendor.sh
```

将占位符替换为实际的本地或远程 Git 地址。仓库不会自动配置远程仓库，
也不会自动发布到 GitHub。

依赖脚本优先复用已经通过校验的安装包。新克隆的仓库可能需要通过
`CHROME_DEB_URL` 提供准确的固定版本安装包，因为官方 `current` 下载
地址会更新。脚本会拒绝校验不一致的文件，不会在宿主机安装软件。

### 2. 创建私有配置

```sh
cp .env.example .env
cp compose.example.yaml docker-compose.yml
openssl rand -hex 32
```

设置较强的 `ADMIN_KEY`，并将生成的随机值填入 `SESSION_SECRET`。
目标网站入口使用 `CHATGPT_URL` 配置；这一历史变量名称保留以兼容现有代码。
示例配置指向公共示例页面，并关闭上游代理。

传输层可以复用，但当前浏览器适配器还包含针对原上游的启动检查和导航
恢复策略。接入其他正式网站前，应审查
[src/browser-manager.js](src/browser-manager.js) 及页面桥接代码。
仅修改入口 URL 不等于完成网站兼容性验证。

### 3. 准备持久化目录

```sh
mkdir -p data/tmp data/home data/cache data/config
sudo chown -R 1007:1007 data
chmod 600 .env
```

镜像内应用使用 UID/GID `1007:1007`。只调整新部署 `data/` 目录的所有权，
不要对无关服务器目录执行递归修改。

### 4. 构建与启动

```sh
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:3003/healthz
```

等待服务健康后，在部署主机打开
[http://127.0.0.1:3003/](http://127.0.0.1:3003/)。
示例默认只绑定回环地址。其他设备需要访问时，应选择合适的内网
`BIND_ADDRESS`，或通过具备访问保护的反向代理入口提供服务。

## 配置

私有 `.env` 与 Compose 环境变量共同提供配置。

| 配置项 | 默认值或示例值 | 作用 |
| --- | --- | --- |
| `ADMIN_KEY` | 必填；不提供适合生产环境的默认值 | 管理员访问码，至少 5 个字符。 |
| `SESSION_SECRET` | 必填 | 前端会话 Cookie 签名密钥，至少 32 个字符；升级时保持不变。 |
| `CHATGPT_URL` | 模板为 `https://example.org/` | 初始目标地址；历史变量名，仍需确认适配器兼容性。 |
| `UPSTREAM_PROXY` | 模板为 `none` | 关闭代理，或指定容器可访问的代理 URL。 |
| `BIND_ADDRESS` | `127.0.0.1` | 示例 Compose 在宿主机上的监听地址。 |
| `HOST_PORT` | `3003` | 示例 Compose 对外端口；容器内部网关端口仍为 3003。 |
| `STREAM_MAX_FPS` | `60` | 采集帧率上限，允许 30–120。 |
| `STREAM_MAX_WIDTH` / `STREAM_MAX_HEIGHT` | `8192` / `4320` | 包含设备像素比的物理画面尺寸上限。 |
| `MAX_ACTIVE_SESSIONS` | `12` | 活跃远程会话数量上限，允许 1–12。 |
| `SESSION_IDLE_MINUTES` | `60` | 已断开远端会话的保留阈值；与固定一分钟的后台断连计时分别控制。 |
| `MAX_UPLOAD_MB` | `500` | 单个上传文件上限；每次请求最多 10 个文件。 |
| `DOWNLOAD_TTL_MINUTES` | `60` | 临时下载文件保留时间。 |
| `LOG_RETENTION_DAYS` | `7` | 应用日志保留天数。 |
| `PUBLIC_HOST` | 模板为空 | 用于核对 HTTPS 证书的域名或 IP。 |
| `ACME_ENABLED` | `false` | 可选证书签发与续期；需要外部能够访问验证监听端口。 |
| `HTTPS_REDIRECT` | `false` | 成功加载可用证书后，将 HTTP 跳转到 HTTPS。 |
| `COOKIE_SECURE` | `false` | 可选的安全 Cookie 要求；HTTPS 请求本身已经使用安全 Cookie。 |

示例 Compose 将容器内的 `DATA_ROOT`、`HOME`、`TMPDIR` 和 XDG 目录
安排在挂载的应用数据目录中。正式部署还可以通过私有配置接入代理容器；
其配置和凭据不属于源码仓库。

## 使用

### 成员工作区

在客户端浏览器访问 `/`，原网站画面会出现在远程画布上。
正常调整浏览器窗口即可，远程视口和像素比自动更新。
每个客户端标签页分别对应自己的输入与窗口会话。

在支持相应功能的网站中，可使用常见操作：选择和复制文字、输入法输入、
粘贴文字或图片、将文件拖到上传区域、使用网站的文件选择器，
以及将支持的下载保存到本机。

切到其他标签页或隐藏浏览器后，开始一分钟宽限计时。到时暂停连接、
画面采集和成员页面脚本，返回后自动重连。远端页面和草稿保留在内存中，
直到 `SESSION_IDLE_MINUTES` 到期，或容量不足时回收已断开的会话；
回收后使用共享资料重新加载上次保存的地址。页面仍可见时，不会仅因
没有打字而断连。

触屏设备可点击输入框使用软键盘、滑动滚动、长按选词并拖动扩展选区。
可见视口随横竖屏和键盘大小变化。若客户端浏览器限制网络往返后打开
原生文件选择器，可以再次点击上传位置。

### 管理员工作区

- `/admin`：使用 `ADMIN_KEY` 验证后进入管理员会话。
- `/admin/signin`：验证后启动独占手动登录工作区，亲自完成登录，再结束该模式以恢复成员会话。
- `/healthz`：只读的服务与浏览器就绪状态。

手动登录期间成员会话暂时停用。该模式沿用持久化资料和代理配置，显示
服务器浏览器工具栏，传递实际键鼠输入，不启用普通页面脚本桥接或浏览器
调试接口。它支持的交互范围比成员模式更窄。

### 界面与品牌

入口标题和布局位于 `public/*.html` 与 `public/styles.css`，
标签图标位于 `public/favicon.svg`。用于自己的部署时，
请替换为有权使用的名称和素材。

## 安全与兼容性

- **成员没有独立访问码，也没有隔离账号。** 能访问成员入口的人可以使用
  共享浏览器状态。对可信用户范围之外提供访问前，应增加网络限制、VPN
  或外部身份验证层。
- Cookie、网站存储和账号历史并不按成员隔离。独立窗口隔离输入和视口，
  不隔离网站权限，也不隔离网站上的业务操作及其影响。
- 凭据和敏感内容应通过 HTTPS 传输。HTTP 可以使用，但部分剪贴板接口
  需要安全上下文及客户端浏览器许可。
- 已有匹配证书可放入 `data/tls/key.pem` 与 `data/tls/fullchain.pem`，
  并配置 `PUBLIC_HOST`。示例不会自动生成证书；ACME 默认关闭，
  启用后需要正确路由验证端口。客户端证书信任由部署者管理。
- 网站兼容性需单独验证。语音、摄像头/麦克风、浏览器扩展、操作系统右键
  菜单及所有原生浏览器弹窗，并未实现与本地浏览器完全等价的支持。
- 无损传输保留的是已经采集的像素，不能使不同操作系统的字体渲染完全
  一致。分辨率与帧率上限也不构成端到端延迟或显示屏实际刷新率保证。
- 仅访问有权使用的网站和共享账号，并遵守相应服务条款。

## 运维

```sh
docker compose ps
docker compose exec app npm run check
docker compose exec app npm test
```

应用日志写入 `data/logs/`；示例关闭了 Docker 容器日志驱动。
上传、临时下载和应用日志具有保留周期控制。
浏览器资料目录属于持久化状态，不能按临时缓存清理。

升级时保留私有配置，再重建应用：

```sh
docker compose build app
docker compose up -d --no-deps app
```

应备份 `.env`、私有 Compose/代理配置和 `data/`。
获取一致的浏览器资料备份前，先停止应用；备份归档放在已忽略的
`backups/` 中，并按凭据妥善保护。恢复浏览器资料时，
同时恢复原来的会话签名密钥。

应用写入通过项目数据挂载集中管理。Docker 镜像、构建缓存及引擎元数据仍
使用宿主机的 Docker 存储，不会仅因指定了项目目录就自动迁入该目录。

```text
.
├── README.md                  # 英文文档
```

## 开发与测试

构建镜像已经包含 QOI WebAssembly 产物，适合直接运行
`npm run check` 和 `npm test`。
在宿主机运行 `npm test` 时，还需要生成 `public/qoi.wasm`，
并安装 Node 依赖。

单元测试覆盖无损像素往返、画面流控与过期 ACK、鼠标事件合并和拖动状态、
绘制就绪、传输压缩、诊断过滤与图标链接。
集成测试网页覆盖视口/DPR 映射、输入法与剪贴板、文件传输、
独立窗口及管理员登录模式切换。

`tests/mobile-e2e.mjs` 覆盖模拟手机／平板触控、横竖屏、键盘尺寸视口、
长按选字和文件操作。`tests/background-e2e.mjs` 使用普通 Chrome 标签页
的可见性，实际等待一分钟宽限期，验证暂停、采集资源释放及自动重连。
这些属于浏览器模拟；有真实设备时，软键盘和操作系统弹窗还需按设备验收。

交互测试只应运行于**独立资料目录、独立数据目录的临时测试部署**，
不要直接测试正式共享账号。
性能工具应同时报告测试负载及测量环节，不用于证明与本地浏览器完全等价。

维护时同步更新中英文文档；依赖变更使用锁文件；保留第三方声明，
并在提交前检查 `git diff --cached`。
不要提交 Cookie、账号、私有配置、画面捕获或运行数据。
